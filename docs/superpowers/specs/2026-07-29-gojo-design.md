# Gojo 设计文档

> 日期：2026-07-29
> 状态：已确认，待写实现计划

## 一、背景与隐喻

AI 编程需要一个「工作空间（Workspace）」，空间下汇集来自不同 Git 仓库的项目，或软链接自其他文件夹的项目，组成一个供 AI Agent 工具编程的整体。

**命名由来**：五条悟老师（Gojo）的专属技能「无量空处」是一种**领域展开**——把对象拉入一个由自己完全掌控的空间。Gojo 做的正是这件事：把散落在各个 Git 仓库、各处文件夹的代码**展开**成一个由你完全掌控的、供 AI Agent 编程的「领域」。工作空间本身即是一种领域。

## 二、领域模型（三层）

```
公共空间 Public Space   (全局唯一 1 个)
  └── 共享 Git 仓库 A、B、C…        ← 只克隆一份

编码空间 Coding Space   (按业务创建，多个)
  ├── 编码空间「电商中台」
  │     ├── 开发项目「订单服务」        ← 一个文件夹
  │     │     ├── git 仓库: order-api      (克隆/切分支/同步)
  │     │     ├── git 仓库: order-worker
  │     │     └── 软链接 → 公共空间/共享库A
  │     └── 开发项目「营销服务」
  └── 编码空间「风控系统」
        └── 开发项目…
```

三种实体：

| 实体 | 数量 | 内容 |
|------|------|------|
| **公共空间 Public Space** | 全局唯一 1 个 | 多个共享 Git 仓库，克隆一份供所有编码空间复用 |
| **编码空间 Coding Space** | 按业务创建，多个 | 装若干开发项目，一个业务一个 |
| **开发项目 Dev Project** | 编码空间下多个 | 一个文件夹，可绑定多个 Git 仓库 + 软链接公共空间的库 |

关键约束：
- 公共空间全局唯一，被所有编码空间共用；共享库只克隆一份，最省磁盘。
- 编码空间按业务隔离，数量不限。
- 软链接方向：**从开发项目指向公共空间的共享库**（`开发项目内路径` → `公共空间/某库`）。
- 开发项目既可**新建子文件夹**，也可**指认一个已存在的文件夹**（后者只补写清单，不改动现有内容）。

## 三、配置存储（中心索引 + 每空间清单）

### 中心索引
`~/Library/Application Support/Gojo/index.json`
- 公共空间路径（单个）
- 所有编码空间的路径列表
- 终端偏好（Terminal / iTerm2 / Warp）等应用级设置

### 每空间清单（自描述、可移植）
- 每个编码空间根目录：`.gojo/workspace.json`
  - 空间名称、创建时间、包含的开发项目列表
- 每个开发项目根目录：`.gojo/project.json`
  - 项目名称
  - 绑定的 Git 仓库列表：`{ url, 目标子目录, 当前分支 }`
  - 软链接映射列表：`{ 公共空间库标识, 项目内链接路径 }`

### 设计理由
- 文件夹**自描述**：换电脑或手动搬动文件夹后，Gojo 读清单即可重建。
- 中心索引只是「书签」：即便丢失，也能靠重新指认空间恢复。

## 四、界面结构（单窗口三栏）

```
┌──────────────┬────────────────────────────┬─────────────────┐
│  侧边栏       │        主内容区              │  [终端▾][访达]  │← 右上角工具栏
│              │                             │                 │
│ 🌐 公共空间   │  当前选中项的详情：          │  终端▾ 下拉:     │
│   ├ 库A       │   · 编码空间 → 项目列表      │   · Terminal     │
│   ├ 库B       │   · 开发项目 → 仓库+软链接   │   · iTerm2       │
│              │     列表、分支、同步状态      │   · Warp         │
│ 📁 编码空间   │                             │                 │
│   ├ 电商中台  │  [+ 克隆仓库] [+ 软链接]      │                 │
│   │  ├ 订单   │  [切换分支] [拉取同步]        │                 │
│   │  └ 营销   │                             │                 │
│   └ 风控系统  │                             │                 │
│ [+ 新建编码空间]                             │                 │
└──────────────┴────────────────────────────┴─────────────────┘
```

- **侧边栏**：顶部公共空间（列共享库），下方所有编码空间（可展开看开发项目）。
- **主内容区**：随选中项变化。
  - 选中编码空间 → 展示其开发项目列表。
  - 选中开发项目 → 展示其 Git 仓库列表（各自分支、同步状态）与软链接列表。
- **右上角工具栏**：
  - 「用终端打开」下拉，可选 Terminal / iTerm2 / Warp，绑定后记住默认。
  - 「用访达打开」直接 `open` 当前选中文件夹。

## 五、核心操作

| 操作 | 说明 |
|------|------|
| 指定公共空间 | 系统文件选择器选一个文件夹，写入中心索引 |
| 公共空间克隆仓库 | 输入 Git URL，`git clone` 到公共空间下 |
| 新建编码空间 | 选文件夹（或新建），生成 `.gojo/workspace.json` |
| 新建开发项目 | 编码空间下新建子文件夹 **或** 指认已存在文件夹，写 `.gojo/project.json` |
| 项目克隆 Git 仓库 | URL → `git clone` 到项目内子目录，记入清单 |
| 切换分支 | 对项目内某仓库执行 `git checkout <branch>` |
| 拉取同步 | 对项目内某仓库执行 `git pull` |
| 软链接公共库 | 选公共空间某库 → `ln -s` 到当前项目内，记入清单 |
| 打开终端 / 访达 | 拉起绑定终端或 Finder，定位到选中文件夹 |

- 所有 Git 与软链接操作调用**系统 git 与系统命令**，复用用户现有的 SSH key、凭据助手、git config；私有/公司仓库可直接克隆，Gojo 内无需管理认证。
- 操作具备加载态与错误提示：clone 失败、分支不存在、软链接目标缺失、网络错误等。

## 六、技术栈与打包

- **技术栈**：SwiftUI + AppKit（菜单栏、`NSOpenPanel` 文件选择、拉起终端/访达）。
- **Git 实现**：调用系统 `git` 命令行（非内嵌 libgit2），复用现有认证。
- **首版平台**：macOS。
- **打包 .dmg**：
  - Xcode 构建 Release。
  - 脚本 `create-dmg`（或 `hdiutil`）打包成可拖入 Applications 的 `.dmg`。
  - 首版**本地自签名**即可运行（首次右键「打开」绕过 Gatekeeper）。
  - 分发给他人时再加 Apple Developer 签名 + 公证（首版不做，避免卡流程）。

## 七、非目标（YAGNI）

- 不做跨平台（Windows/Linux），首版仅 macOS。
- 不内嵌终端 / AI Agent 交互界面，只负责组装文件夹结构 + 拉起外部工具。
- 不在应用内管理 Git 认证 / 密钥。
- 首版不做 Apple 签名与公证。
- 不支持多个公共空间。
