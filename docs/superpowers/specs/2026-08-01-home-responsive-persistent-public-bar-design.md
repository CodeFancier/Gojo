# Gojo 首页响应式轮播与持续公共栏设计

> 日期：2026-08-01  
> 状态：已确认，待实施  
> 范围：首页编码空间轮播、首页与编码空间详情共用的底部公共空间栏，以及详情页公共项目搜索。

本文档替代 `2026-08-01-home-space-sections-design.md` 中“公共空间在上、编码空间在下”的布局约定。空间领域模型、公共空间详情页、成员模式和拖放语义继续沿用既有设计。

## 1. 目标

当前首页的编码空间和公共空间层级需要再次调整：编码空间应成为上方主内容，公共空间应固定在底部，并在进入编码空间详情后继续保留。与此同时，编码空间卡片需要随窗口尺寸变化，详情页的公共项目区域需要更大、更易读并支持搜索。

本次目标：

1. 首页改为“上方编码空间、下方公共空间”。
2. 首页与编码空间详情共用同一个持续存在的公共空间栏。
3. 编码空间保留焦点轮播，但卡片尺寸随窗口平滑变化。
4. 放大公共空间标题、内容、搜索框和项目卡片。
5. 在编码空间详情中按项目名称和 Git URL 实时搜索公共项目。
6. 重新搭配两类空间色调，同时保持深色 Gojo 品牌体系。

界面名称继续使用“编码空间”，不改为“开发空间”。

## 2. 已确认视觉方向

采用“深海蓝 + 青绿”配色：

- 编码空间：深海蓝。焦点描边和高光使用现有蓝色语义，背景可补充低饱和深蓝层次。
- 公共空间：青绿色。它表达共享、连接和流动，与编码空间蓝形成清楚但协调的分区。
- 页面背景继续使用现有深色渐变。
- 类别区分不只依赖颜色，同时保留“编码空间 / 公共空间”标题、`shippingbox.fill` / `globe` 图标和不同组件形态。

新增颜色必须集中在 `Motion.swift` 的语义色板中，不允许在视图里散落 RGB 值。青绿色需要提供强调色、表面填充和描边透明度的统一用法。

## 3. 首页布局

首页自上而下为：

```text
品牌字标
编码空间标题
响应式焦点轮播
分页指示器
持续公共空间栏（摘要模式）
```

### 3.1 编码空间标题与轮播

标题继续使用“编码空间”。轮播保留现有交互：

- 滚动或左右方向键切换焦点。
- 激活非焦点卡只把它移到中央。
- 再次激活焦点卡才进入空间或创建新空间。
- 保留焦点发光、成员缩略墙和 Reduce Motion 分支。

卡片不再使用固定 `240 × 200` / `150 × 150` 两档，而由可用窗口尺寸计算：

- 焦点卡宽度在约 `240–360pt` 之间平滑变化。
- 焦点卡高度随可用内容高度变化，但不得侵占分页指示器或底栏。
- 侧卡宽高按焦点卡的固定比例缩放，仍保持明显的焦点层级。
- 横向内边距使用当前焦点卡宽度计算，保证首尾卡都能居中。
- 最小内容区 `720 × 460pt` 下，品牌字标、标题、焦点卡、分页指示器和公共栏均可访问且不重叠。
- 辅助字号下允许页面纵向滚动，不禁止 Dynamic Type。

窗口连续缩放时，卡片尺寸使用现有运动规范平滑更新；Reduce Motion 开启时直接更新尺寸，不做缩放位移动画。

### 3.2 公共空间摘要模式

公共空间栏固定在首页底部，不参与上方轮播滚动。摘要模式显示：

- `globe` 图标与“公共空间”标题。
- 公共项目总数。
- 已克隆和待同步数量。
- 打开公共空间的动作提示。

标题使用 `.title3.bold()`；主要状态与统计使用 `.body`；辅助说明使用不小于 `.callout` 的语义字号。整栏可点击并进入公共空间详情。

未指定公共空间时显示“尚未指定公共空间”；已指定但没有项目时显示“暂无公共项目”。

## 4. 编码空间详情布局

进入编码空间后，上方主体显示现有顶栏、成员网格和拖放覆盖层；底部公共空间栏不离开视图层级，只从摘要模式过渡到搜索与拖拽模式。

详情模式显示：

- 放大的“公共空间”标题和项目统计。
- 标准高度不低于 32pt 的搜索框。
- 放大的公共项目卡片，显示项目名；空间允许时可显示 URL 或克隆状态。
- 横向滚动项目列表，保留从公共项目拖入编码空间的能力。

搜索框只在编码空间详情显示；首页保持简洁摘要。底栏在不同编码空间之间切换时保留搜索词，返回首页时清空。

## 5. 搜索行为

搜索为本地实时过滤，不修改 `AppState.publicProjects`：

- 同时匹配项目名称和 Git URL。
- 不区分大小写。
- 查询前后空白被忽略。
- 空查询显示全部项目。
- 无匹配结果显示“没有匹配的公共项目”。
- 搜索后的项目仍可拖拽，拖拽 payload 和模式选择完全沿用现有实现。

搜索不触发网络请求，不写配置，也不改变项目排序。

## 6. 组件与状态边界

### 6.1 `ContentView`

`ContentView` 负责组合“可切换的上方路由内容 + 持续公共空间栏”。公共栏模式由当前 `Route` 派生：

- `.shelf` → `.summary`
- `.codingSpace` / `.shelfDropping` → `.searchable`
- `.publicSpace` → `.hidden`

公共项目拖拽 ID 提升到足以被公共栏和 `CodingSpaceDomain` 共同访问的视图状态；不写入 `AppState`，因为它只属于当前拖拽会话。

### 6.2 `PersistentPublicSpaceBar`

新增统一组件，负责摘要和搜索两种模式。它消费：

- 当前模式。
- `publicSpaceFolder` 是否存在。
- `publicProjects`。
- 打开公共空间动作。
- 拖起公共项目回调。

组件内部持有搜索词，并在模式从搜索返回摘要时清空。过滤逻辑调用纯函数，不在 `body` 内重复实现。

### 6.3 `CodingSpaceDomain`

移除内部旧 `ProjectTray`，继续负责成员网格和双落区。公共栏拖起项目后，通过绑定把项目 ID 传给 `CodingSpaceDomain`，由现有 `DropZones` 完成 Git 克隆 / 软链接选择。

### 6.4 `CodingSpaceCarousel` 与 `ShelfCard`

`CodingSpaceCarousel` 根据几何尺寸获得卡片指标并传给 `ShelfCard`。`ShelfCard` 不直接读取全局窗口尺寸，只消费焦点宽高、侧卡宽高等明确参数，保持组件边界清晰。

## 7. 纯逻辑与数据流

新增两个可测试的纯逻辑单元：

1. `PublicProjectSearch.filter(_:query:)`：返回名称或 URL 匹配的项目。
2. `CarouselCardMetrics`：根据视口宽高和 Reduce Motion 无关的约束，计算焦点卡、侧卡和水平居中内边距。

数据流：

```text
AppState.publicProjects
        │
        ├── 首页摘要统计
        └── PublicProjectSearch + query
                    │
                    └── 详情底栏可见项目 → 原有 DragPayload

窗口 Geometry
        │
        └── CarouselCardMetrics → ShelfCard 尺寸与轮播内边距
```

两个纯逻辑单元不持久化状态、不依赖 SwiftUI，放入 `GojoCore` 并由 `GojoCoreTests` 覆盖。

## 8. 无障碍与键盘

- 公共空间栏保持原生 `Button` / `TextField` 语义。
- 搜索框提供清晰标签“搜索公共项目”。
- 公共项目拖拽卡片同时提供稳定项目名称；搜索状态不会改变其 ID。
- 编码空间卡继续提供按钮角色、居中状态和两段式动态提示。
- 颜色不是唯一分类手段。
- 辅助字号下允许纵向滚动，公共栏标题和内容不被截断。
- Reduce Motion 下取消轮播尺寸、滚动和路由的位移动画。

## 9. 错误与空状态

本次不新增网络、存储或异步错误路径。继续使用现有全局错误提示处理创建、克隆和拖入失败。

公共栏覆盖以下状态：

| 状态 | 首页摘要 | 编码空间详情 |
|---|---|---|
| 未指定公共空间 | 尚未指定公共空间 | 提示进入公共空间进行设置，不显示搜索框 |
| 已指定、无项目 | 暂无公共项目 | 显示搜索框和“公共空间暂无项目” |
| 有项目、空查询 | 显示统计 | 显示全部项目 |
| 有项目、无匹配 | 不适用 | 显示“没有匹配的公共项目” |

## 10. 测试与验收

自动测试：

- `PublicProjectSearch`：空查询、前后空白、名称匹配、URL 匹配、大小写、无匹配和稳定顺序。
- `CarouselCardMetrics`：最小窗口、宽窗口、上下限钳制、侧卡比例、居中内边距。
- 现有 `CarouselFocusTests`、路由、拖放 payload 和全部回归测试继续通过。
- `swift build` 与 `swift test` 成功。

真实 UI 验收：

1. 首页编码空间位于上方，公共空间位于底部。
2. 窗口从 `720pt` 连续放宽时，焦点卡和侧卡平滑变大且首尾仍可居中。
3. 进入编码空间时公共栏保持在底部，只展开搜索与项目区域。
4. 搜索名称和 URL 均能实时过滤；无结果空态正确。
5. 过滤后的项目仍能拖入 Git 克隆 / 软链接落区。
6. 公共标题、统计、搜索和项目卡片明显大于当前版本。
7. 最小窗口、最大辅助字号、键盘导航、VoiceOver 和 Reduce Motion 下无重叠或不可达操作。

## 11. 不在范围内

- 不修改“编码空间”名称。
- 不修改公共空间详情页的项目管理流程。
- 不增加远程搜索、排序、标签或收藏。
- 不改变成员模式、拖放 payload、克隆或软链接语义。
- 不引入第三方依赖。
