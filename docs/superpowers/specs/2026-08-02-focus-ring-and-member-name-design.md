# 编码空间焦点框与项目名显示优化设计

## 目标

- 首页编码空间轮播获得键盘输入时，不显示系统蓝色焦点框。
- 保留左右方向键切换、两步激活、VoiceOver 与 Reduce Motion 行为。
- 进入编码空间后，让项目卡片和项目名获得更多横向空间。

## 交互设计

### 无焦点环键盘操作

使用一个 macOS 13 可用、无焦点环的 AppKit 键盘接收视图替代轮播容器现有的 SwiftUI `.focusable()`。接收层成为第一响应者后处理左右方向键，并把方向传回 `CodingSpaceCarousel` 的现有 `step` 逻辑。

该调整只隐藏整个轮播区域的系统蓝色焦点框。居中卡片原有的描边、光晕、分页状态和辅助功能语义保持不变。

接收视图不拦截未处理的按键；除左右方向键外，其余事件继续交给响应链。鼠标点击卡片、首尾居中及二次激活行为保持不变。

## 项目卡片布局

编码空间详情的自适应网格列宽由当前 `168–220pt` 调整为 `220–280pt`。`MemberCard` 不再固定为 `168pt`，而是填满网格分配的列宽。

项目名称继续保持一行，使用中间截断，以便在极长名称下同时保留开头和结尾。分支名、记忆入口、悬停操作栏、右键菜单及拖拽行为不变。

在最小 720pt 窗口内预计保持三列；更宽窗口按可用宽度自动增加列数或卡片宽度。

## 可访问性与兼容性

- 键盘接收层设置为无焦点环，但仍可成为第一响应者。
- 轮播卡片继续使用原生 `Button` 和现有 VoiceOver 标签、值与提示。
- 项目名称不限制用户字号，卡片宽度由网格决定。
- 不提升当前 macOS 13 最低系统版本，不增加第三方依赖。

## 验证

- 构建并运行完整测试。
- 在实际应用中点击轮播并使用左右方向键，确认焦点切换正常且不出现外围蓝框。
- 在 720pt 和较宽窗口中进入编码空间，确认项目卡片自适应、长名称显示更完整，且悬停操作、拖拽和右键菜单正常。
- 检查 VoiceOver 标签、Reduce Motion 分支和代码空白错误。
