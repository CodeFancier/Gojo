# Gojo 扁平化与公共项目模式 设计文档

> 日期：2026-07-29
> 状态：已确认，待写实现计划
> 关系：本文档取代 `2026-07-29-gojo-design.md` 中「开发项目中间层」与「公共空间靠扫描识别」的相关部分，其余（命名隐喻、技术栈、打包、终端/访达）仍然有效。

## 一、背景

在原三层模型（公共空间 → 编码空间 → 开发项目 → 仓库）落地后，提出四条增强需求：

1. 打开编码空间时**自动识别**当前文件夹内的 git 仓库。
2. 编码空间内多个仓库支持**显示分支名称**。
3. 公共空间的项目支持**只定义 git 地址**，点击 Clone 按钮才同步下来。
4. 编码空间创建后，公共空间的项目可**拖入**该空间，并可**切换模式**：1) 软链接模式 2) Git 模式。

这四条共同指向一个结构性调整：**去掉「开发项目」中间层**，让编码空间直接装仓库。

## 二、五个已确认决策

| # | 决策 | 取值 |
|---|------|------|
| 1 | 仓库层级 | **扁平化**：编码空间直接装仓库，取消「开发项目」中间层 |
| 2 | Git 模式含义 | **独立克隆（clone）**，各自 `.git` 与工作目录，可独立切分支 |
| 3 | Git 模式克隆源 | **从公共项目的远程 URL 克隆**（origin 指向真远程，push/pull 直达上游） |
| 4 | 公共空间模型 | **清单驱动**：记 `{名称, URL, 是否已克隆}`，clone 按需触发 |
| 5 | 模式切换 | **可随时来回切**，Git→软链接若有未提交/未推送改动则弹破坏性确认 |

补充决策（设计推导，非用户显式确认，如需调整请指出）：

- **成员真相来源：扫描优先**。编码空间「有哪些成员」以文件系统扫描为准；清单只补充记录「绑定了公共项目」的成员（来源 + 模式）。独立仓库不入清单，纯扫描 + 实时读分支。
- **不做旧数据迁移垫片**（YAGNI）。新结构直接取代旧「开发项目」清单结构；本地无需保留的旧数据不迁移。

## 三、领域模型（扁平化后·两层）

```
公共空间 Public Space   (全局唯一 1 个)
  └── 公共项目 A、B、C…              ← 每个 = {名称, git URL, 是否已克隆}
                                        cloned=false 时只有定义、尚未拉下来

编码空间 Coding Space   (按业务创建，多个)
  ├── 编码空间「电商中台」
  │     ├── order-api        (独立仓库，含 .git)          ← 扫描识别
  │     ├── shared-lib       (公共项目·软链接模式) → 公共空间/shared-lib
  │     └── payment-core     (公共项目·Git 模式，独立 clone)
  └── 编码空间「风控系统」
```

三种实体：

| 实体 | 数量 | 内容 |
|------|------|------|
| **公共空间** | 全局唯一 1 个 | 多个**公共项目**（名称 + URL + 是否已克隆） |
| **编码空间** | 按业务多个 | 直接装若干**成员仓库**（独立 / 公共·Git / 公共·软链接） |
| **成员仓库** | 编码空间下多个 | 编码空间内一个直接子文件夹 |

## 四、成员仓库的三种形态

| 形态 | 文件系统 | 清单是否记录 | 分支 |
|------|---------|------------|------|
| **独立仓库** | 直接子文件夹含 `.git` | 否（纯扫描） | 实时读 |
| **公共项目·Git 模式** | 独立 clone（含 `.git`），源为公共项目**远程 URL** | 是：`source=public(id)` + `mode=git` | 实时读，可独立切分支 |
| **公共项目·软链接模式** | 符号链接 → 公共空间的本地 clone | 是：`source=public(id)` + `mode=symlink` | 跟随公共库 |

**打开/刷新编码空间的识别流程**：

1. 扫描编码空间的直接子文件夹（跳过 `.gojo`、隐藏项）。
2. 对每个成员判定形态：
   - 是符号链接 → 软链接成员（读清单确认绑定的公共项目）。
   - 含 `.git` → git 仓库，实时 `git rev-parse --abbrev-ref HEAD` 读当前分支（满足需求2）。
3. 结合清单标注每个 git 仓库是「独立」还是「公共·Git 模式」。
4. 结果缓存在内存态，提供手动刷新。

## 五、配置存储

### 中心索引（不变）
`~/Library/Application Support/Gojo/index.json`
- `publicSpacePath`、`codingSpacePaths[]`、`terminalPreference`

### 公共空间清单（新增）
`公共空间根/.gojo/public.json`
```
{
  "projects": [
    { "id": UUID, "name": "shared-lib", "url": "git@…:shared-lib.git", "cloned": false }
  ]
}
```
- `cloned=false`：只有定义、还没 clone。
- 打开公共空间时也扫描已有子文件夹；扫到但清单没有的，自动补一条 `cloned=true`（兼容手动放入的库）。

### 编码空间清单（重构）
`编码空间根/.gojo/workspace.json`
```
{
  "name": "电商中台",
  "members": [
    { "folderName": "shared-lib",   "source": {"public": UUID}, "mode": "symlink" },
    { "folderName": "payment-core", "source": {"public": UUID}, "mode": "git" }
  ]
}
```
- 只记录**绑定了公共项目**的成员（需要持久化「来源 + 模式」这类扫描得不到的信息）。
- 独立仓库不出现在 `members`，靠扫描发现。

### 设计理由
- 文件夹自描述：换机 / 手动搬动后，扫描 + 清单即可重建。
- 分支不落盘：一律实时读，避免陈旧。

## 六、核心操作

### 公共空间（需求3）
| 操作 | 说明 |
|------|------|
| 新增公共项目 | 输入名称 + git URL，只写清单 `cloned=false`，**不立即 clone** |
| Clone 公共项目 | 对 `cloned=false` 的项点 Clone → `git clone url` 到 `公共空间/名称` → 成功后 `cloned=true` |
| 扫描兼容 | 打开公共空间时扫描子文件夹，补录未在清单的已克隆库 |

### 编码空间成员（需求1、2、4）
| 操作 | 说明 |
|------|------|
| 自动识别 | 打开编码空间扫描子文件夹，识别独立仓库 / 软链接（需求1） |
| 显示分支 | 每个 git 仓库实时读当前分支并展示（需求2） |
| 拖入公共项目 | 从公共空间拖项目到编码空间 → 选模式（软链接 / Git）→ 落地 + 记清单（需求4） |
| 切分支 | 对某 git 成员 `git checkout <branch>` |
| 同步 | 对某 git 成员 `git pull --ff-only` |
| 切换模式 | 软链接 ↔ Git，见下（需求4） |

### 模式切换（需求4，含破坏性确认）
- **软链接 → Git**：删符号接 → 从公共项目**远程 URL** clone 到同名文件夹 → 清单 `mode=git`。
- **Git → 软链接**：
  1. 检查该 clone 是否有未提交（`git status --porcelain`）或未推送（`git log @{u}..` / 无上游视为有风险）改动。
  2. 有 → **弹确认警告**：切回会删掉本地 clone、丢失这些改动。用户确认后才继续。
  3. 删文件夹 → 建符号链接指向公共库 → 清单 `mode=symlink`。
- **前置**：软链接模式要求公共项目**已 clone**（链接指向本地那份）；若未克隆，提示「需先克隆公共库」并中止。

## 七、界面结构

沿用单窗口三栏 + 右上角工具栏（终端 / 访达）。改动：

- **侧边栏**：
  - 公共空间：列出公共项目，每项标「已克隆 / 未克隆」；未克隆项旁有 **Clone 按钮**。
  - 编码空间：展开后**直接列成员仓库**（不再有开发项目层）。每行显示分支名 + 模式图标（🔗软链接 / ⑂Git / 📦独立）。
- **详情区**：
  - 选中公共空间 → 公共项目列表（名称、URL、克隆状态、Clone 按钮、新增项目入口）。
  - 选中编码空间 → 成员列表；每行：文件夹名、模式、分支（下拉可切）、同步按钮、模式切换按钮。
- **拖拽**：公共空间列表项拖到编码空间 → 弹「选择模式：软链接 / Git」→ 落地。
  - **退化**：若 SwiftUI 拖拽实现受阻，退化为右键菜单/按钮「添加到编码空间…」，会如实告知，不谎称拖拽已实现。

## 九、非目标（YAGNI）

- 不做旧「开发项目」清单的迁移垫片。
- Git 模式不支持从公共库本地克隆（只从远程 URL）。
- 不支持嵌套分组（编码空间下不再有项目层，也不引入新分组层）。
- 软链接模式不支持指向未克隆的公共项目（必须先 clone）。
- 其余非目标沿用原 spec（不跨平台、不内嵌终端、不管理 git 认证、首版不签名公证）。
